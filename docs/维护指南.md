# 博客维护指南

线上地址：https://starlitvale.github.io/

本站使用 Astro 与 Mizuki 9.0。源码目录为 `C:\Users\ASUS\Desktop\个人博客\blog`，所有命令均在该目录运行。运行环境为 Node.js 24 与 pnpm 11.5.3。

## 日常操作

- 双击桌面文件夹里的 **本地预览.cmd**，浏览器会打开 `http://127.0.0.1:3000/`，保存修改后自动更新。关闭命令窗口即停止预览。
- 双击 **新建文章.cmd**，输入标题和可选的英文文件名。生成的 Markdown 草稿会用默认编辑器打开，可继续用 Typora 写作。
- 双击 **发布博客.cmd**，脚本检查并构建网站，通过后提交和推送至原 GitHub 仓库，由 GitHub Actions 自动部署。
- 双击 **打开博客.cmd**，访问线上网站。

发布结果查看：https://github.com/Starlitvale/starlitvale.github.io/actions

## 文章与图片

文章放在 `src/content/posts/`，支持 `.md` 和 `.mdx`，也支持每篇文章一个子文件夹、正文命名为 `index.md`。

```yaml
---
title: 文章标题
published: 2026-11-02
description: 一句话摘要
image: ""
tags: [学习, 随笔]
category: 记录
draft: true
lang: ""
typora-copy-images-to: ./my-post.assets
---
```

新文章默认是草稿，准备公开时将 `draft: true` 改为 `draft: false`。草稿不会进入正式页面和搜索，但提交到公开仓库后的源文件仍可被他人看到。私密笔记请保存在博客源码之外。

图片放在文章旁的 `.assets` 文件夹，Markdown 使用相对路径，例如 `![图片说明](./my-post.assets/photo.webp)`。Typora 的图像设置建议启用“复制图片到指定路径”“优先使用相对路径”和“插入时自动转义图片 URL”。不要引用电脑上的 `C:\...` 绝对路径。也可将公共图片放在 `public/images/`，用 `/images/photo.webp` 引用。

原来的四篇文章未迁入新版。恢复备份时，将 Markdown 和配套图片复制到文章目录，检查 frontmatter 和图片路径，再预览、发布即可。首页的 `new-beginning.md` 是一篇可自由修改或删除的开篇文章。

## 个性化设置

| 内容 | 文件 |
| --- | --- |
| 站名、语言、网址、主题色、横幅文字和轮播图 | `src/config/siteConfig.ts` |
| 头像、作者名、简介和社交链接 | `src/config/profileConfig.ts` |
| 顶部导航 | `src/config/navBarConfig.ts` |
| 侧栏内容及位置 | `src/config/sidebarConfig.ts` |
| 侧栏公告 | `src/config/announcementConfig.ts` |
| 关于页面 | `src/content/spec/about.md` |
| 全屏背景 | `src/config/backgroundWallpaper.ts` |

默认沿用 Mizuki 配套的横幅素材；替换图片时，分别修改 `banner.src` 和全屏背景配置。主题的浅色/深色、配色和布局切换可直接在网页设置面板操作。

未填写个人数据的相册、番剧、设备、项目等页面默认关闭，演示数据已清空。需要时在 `siteConfig.featurePages` 中开启，填写 `src/data/` 对应数据，并添加导航。音乐、看板娘、评论和第三方统计默认关闭，配置完成后可自行开启。

## 命令与故障处理

```powershell
npx --yes pnpm@11.5.3 install --frozen-lockfile
npx --yes pnpm@11.5.3 dev --host 127.0.0.1 --port 3000
npx --yes pnpm@11.5.3 check
npx --yes pnpm@11.5.3 build
```

本地搜索以正式构建生成的 Pagefind 索引为准。如要验证搜索，可先构建再运行 `npx --yes pnpm@11.5.3 preview --host 127.0.0.1 --port 3000`。

本地 `.env` 设置 `ENABLE_CONTENT_SYNC=false`，GitHub Actions 中也固定关闭外部内容同步，文章直接在本地管理。`.env` 不上传到仓库。请保留 `.gitignore`，不要提交凭证或密钥。

如果端口已被占用，先关闭之前的预览窗口。发布失败时按窗口提示处理，检查失败不会推送；GitHub 登录失效时，按 Git Credential Manager 的正常流程重新登录。
